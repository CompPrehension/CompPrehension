# reclassify — пересчёт метаданных банка вопросов `expression_dt`

Утилита пересчитывает метаданные вопросов домена выражений в таблице `questions_meta`:
`concept_bits`, `trace_concept_bits`, `skill_bits`, `violation_bits`, `integral_complexity`,
`distinct_errors_count`, `solution_structural_complexity`, `solution_steps`.

Тела вопросов (`questions_data`), имена, `template_id`, `tag_bits` и `law_bits` не изменяются.
Обрабатываются только записи формата `_version = 12`.

## Сборка

```bash
./mvnw -q -Ptools -pl tools/reclassify -am package -DskipTests
```

Модуль подключается Maven-профилем `tools` и не участвует в сборке проекта по умолчанию.
Результат — `tools/reclassify/target/reclassify.jar` (домен и драйвер MySQL включены, Spring не требуется).

## Подключение к базе данных

Параметры подключения задаются одним из способов:

- явно: `--url "jdbc:mysql://host:3306/db" --user USER --password PASSWORD`;
- из файла окружения: `--env FILE` (по умолчанию `.env/compprehension-env.env` в текущем каталоге);
  используются переменные `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD`.

## Запуск

```bash
# отчёт об изменениях без записи в базу
java -jar tools/reclassify/target/reclassify.jar --dry-run

# пересчёт и запись
java -jar tools/reclassify/target/reclassify.jar

# отдельные вопросы
java -jar tools/reclassify/target/reclassify.jar --ids 1748917,1743802 --dry-run --verbose

# точный режим, один из четырёх параллельных процессов
java -jar tools/reclassify/target/reclassify.jar --solver --shard 0/4
```

| Флаг | Назначение |
|---|---|
| `--dry-run` | вывести отчёт, ничего не записывая |
| `--solver` | точный режим: биты ошибок и умений и число шагов вычисляются решателем (см. ниже) |
| `--delete-invalid` | удалять записи `questions_meta` вопросов, которые не удаётся пересчитать; по умолчанию они только перечисляются |
| `--ids a,b,c` | обработать только указанные идентификаторы |
| `--shard K/N` | обработать только записи с `id % N == K`; позволяет запустить N процессов параллельно |
| `--batch N` | размер выборки и транзакции (по умолчанию 1000) |
| `--verbose` | выводить также неизменившиеся вопросы и трассировки исключений |

## Режимы пересчёта

**Режим по умолчанию.** Метаданные вычисляются методом `MeaningTreeOrderQuestionBuilder.metadataRecalculate` —
тем же кодом, которым классифицируются вновь генерируемые вопросы. Это обеспечивает единообразие
банка и новых вопросов; весь банк обрабатывается за несколько минут. Ограничения режима совпадают с
ограничениями генератора: возможные ошибки определяются по структуре выражения, а не по фактическому
поведению дерева решений, поэтому набор ошибок может быть объявлен шире реального; число шагов для
выражений с операторами строгого порядка (`&&`, `||`, `?:`) вычисляется приближённо.

**Режим `--solver`.** Дополнительно к генератору вопрос прогоняется через дерево решений: для каждого
корректного префикса решения проверяется каждый возможный следующий ответ, найденные законы и умения
объединяются, умения приводятся к базовым. Законы, которые дерево не выдаёт (`early_finish`,
`*_having_associativity_*`), берутся из генератора. Число шагов равно длине найденного решения,
сложность пересчитывается по формуле генератора. Результат точно соответствует поведению решателя,
однако требует порядка n² прогонов решателя на вопрос из n операторов (десятки секунд на вопрос),
поэтому режим рассчитан на выборочный запуск по `--ids` либо на параллельный запуск по `--shard`.

## Вопросы, которые не удаётся пересчитать

- `INVALID` — `metadataRecalculate` отвергает вопрос (`allChecksArePassed == false`): выражение не
  проходит проверку перевод → токены → перевод. Как правило, это мутации с некорректными
  идентификаторами.
- `FAILED` — тело вопроса не десериализуется текущей версией MeaningTree; исключение возникает при
  загрузке дерева выражения, до пересчёта. Такие вопросы непригодны и для выдачи студентам:
  `makeQuestion` завершается тем же исключением.

По умолчанию обе категории только перечисляются в отчёте. С флагом `--delete-invalid` соответствующие
записи `questions_meta` удаляются; записи `questions_data` сохраняются. Перед удалением рекомендуется
просмотреть список через `--dry-run`.

## Формат вывода

```
CHANGED  1748917 wp-sx_+_sb_w_c++-1098429591_v
    violations -[error_base_higher_precedence_right] +[error_base_higher_precedence_left]
    complexity 0,4624 -> 0,5000
INVALID  1749001 ...
FAILED   1742797 ...: java.lang.NullPointerException: ...

scanned=7473 changed=6681 unchanged=495 invalid=284 failed=13
```

Для каждого изменённого вопроса выводятся удалённые (`-`) и добавленные (`+`) концепты, ошибки и
умения, а также изменения числа шагов и сложности. Код возврата 2, если встретились записи `FAILED`
и их удаление не запрашивалось; в остальных случаях 0.
