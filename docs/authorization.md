# Авторизация

Проверка всегда звучит одинаково: **есть ли у пользователя право P в контексте C**.

## Контексты

Контексты образуют дерево:

```
ROOT                        вся система
├── GLOBAL                  упражнения вне курсов и пользователи сайта
└── EDUCATION_RESOURCE      одна LMS
    └── COURSE              курс этой LMS
```

Роль, выданная в контексте, действует в нём и во всех вложенных: админ образовательного ресурса —
во всех курсах своей LMS, `ADMIN` — везде. Вверх и вбок права не распространяются: роль в курсе
не действует ни в соседнем курсе, ни в GLOBAL, роль в GLOBAL не действует в курсах.

## Права

| право | GLOBAL | курс |
|---|---|---|
| `VIEW_EXERCISE_LIST` | — | листать упражнения курса |
| `VIEW_EXERCISE_CARD` | — | открывать карточку упражнения курса |
| `SEARCH_QUESTION_BANK` | — | искать в банке вопросов |
| `CREATE_EXERCISE` | создать упражнение | создать упражнение в курсе; оборвать наследование — сделать из унаследованного упражнения свою копию |
| `EDIT_EXERCISE` | править упражнение | править упражнение курса |
| `DELETE_EXERCISE` | удалить упражнение | удалить упражнение курса |
| `SOLVE_EXERCISE` | решать упражнение по прямой ссылке | решать упражнение курса |
| `CREATE_DEBUG_ATTEMPT` | отладочная попытка | отладочная попытка |
| `VIEW_OTHER_ATTEMPTS` | читать чужие попытки вне курсов | читать чужие попытки курса |
| `COPY_EXERCISE_TO_GLOBAL_POOL` | скопировать упражнение курса в GLOBAL | — |
| `VIEW_EXERCISE_USAGE` | видеть, в каких курсах используется упражнение | — |
| `LINK_POOL_EXERCISE_TO_COURSE` | — | состав курса: наследовать упражнение из GLOBAL, отвязать |
| `CREATE_LMS_ACTIVITY` | — | экран настройки курса из LTI; сборка активностей deep-linking |
| `VIEW_COURSE` | — | видеть этот курс в списке своих курсов |

`VIEW_COURSE` в `ROOT` — видеть в списке своих курсов все курсы системы.

`REGISTER_LMS` проверяется только в `ROOT`: подключать LMS по ссылке регистрации и видеть подключённые.

Писать в попытку (отвечать, генерировать вопросы) может только её владелец при наличии `SOLVE_EXERCISE`.
Чужую попытку можно только читать.

### Способности

Некоторые права не привязаны к объекту — это способности пользователя (`SystemCapability`). Назначаются
они, как и права, через роль в каком-то контексте, но проверяются без контекста: способность есть, если
её даёт хоть одна роль пользователя где угодно. Хранятся в той же таблице `permission`.

| способность | что даёт |
|---|---|
| `VIEW_GLOBAL_POOL` | листать упражнения GLOBAL, открывать их карточки и брать их как источник копирования; искать в банке вопросов вне курса |
| `DEBUG_BANK_QUESTION` | генерировать вопрос по метаданным банка и работать с ним |

## Роли

Роль назначается **в одном контексте** и действует в нём и во вложенных. Попытка назначить роль
не в свой контекст падает с `IllegalArgumentException`.

| роль | где назначается | что может |
|---|---|---|
| `ADMIN` | `ROOT` | всё и везде |
| `GLOBAL_EXERCISE_AUTHOR` | GLOBAL | упражнения вне курсов: создавать, править, решать, отлаживать, читать чужие попытки, копировать в GLOBAL упражнения курсов. Удалять — **нет** |
| `EDUCATION_RESOURCE_ADMIN` | обр. ресурс | всё, что может `TEACHER`, но сразу во всех курсах своей LMS |
| `TEACHER` | курс | свой курс: состав, упражнения целиком, решение, отладка, чтение чужих попыток; упражнения GLOBAL — на просмотр |
| `ASSISTANT` | курс | свой курс: смотреть, решать, читать чужие попытки; не менять |
| `STUDENT` | GLOBAL и курс | только решать |

У `GLOBAL_EXERCISE_AUTHOR` намеренно нет `DELETE_EXERCISE`: удаление упражнения из GLOBAL каскадом
задевает все наследующие курсы и необратимо, а владельца у упражнения пока нет.

## Расположение прав и ролей и их связей

Набор прав роли продублирован, и обе копии обязаны совпадать:

- класс [`AuthObjects`](../modules/core-api/src/main/java/org/vstu/compprehension/businesslogic/auth/AuthObjects.java)
- таблицы `role`, `permission`, `role_permission`, `permission_scope`.

**!!! Любое изменение ролевой модели — это пара «правка enum + правка бд» !!!**
