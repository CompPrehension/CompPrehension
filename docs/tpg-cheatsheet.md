# Шпаргалка по LOQI: модель предметной области и граф мыслительных процессов

LOQI — язык its_DomainModel. На нём описываются модель предметной области (классы, объекты, связи) и граф мыслительных
процессов (ГМП, `tpg`): дерево решений, по которому ризонер (its_Reasoner) проходит от корня через развилки к выводу
`correct`, `error` или `null` и оставляет трассу.

Источники истины: грамматика `its_DomainModel/src/main/antlr4/its/model/definition/loqi/LoqiGrammar.g4`,
сборка дерева — `TreeLoqiBuilder`, вычисление — `its_Reasoner/.../nodes/DecisionTreeReasoner.kt`.
Комментарии — `//` и `/* */`.

## Файлы модели

| файл | что в нём |
|---|---|
| `domain.loqi` | основная модель: классы, перечисления, объекты |
| `tag_<тег>.loqi` | данные под-области; при выборе тега сливаются с основной моделью |
| `tree.loqi` | главное дерево |
| `tree_<имя>.loqi` | дерево `<имя>`, вызывается через `subcall("<имя>", ...)` |

В файле дерева ровно один `tpg`, вокруг него — `lambda`, `fragment` и `meta for`. Лямбды и фрагменты видны только
в своём файле.

## Модель предметной области

```loqi
enum Color {
    red [ RU.localizedName = "красный" ; EN.localizedName = "red" ; ],
    blue,
} [ RU.localizedName = "цвет" ; ]

class Item {
    class prop isFragile: bool = false ;      // свойство класса, значение по умолчанию
    obj prop weight: int ;                    // свойство объекта
    obj prop color: Color ;
    rel directlyIn(Item) : partial ;          // шкала: у предмета не больше одного «контейнера»
    rel holds(Item) : opposite to directlyIn ;
    rel inside(Item) : transitive to directlyIn ;
    rel slot<index : int>(Item) : {1 -> *} ;  // отношение с параметром и кардинальностью
    rel sameColorAs(Item) ;                   // без указаний — {* -> *}
} [ RU.localizedName = "предмет" ; ]

class Vase : Item {
    isFragile = true ;                        // значение свойства класса у наследника
}

values for class Item { isFragile = false ; } // значения свойств класса отдельно, например из тега

obj box : Item { weight = 5 ; color = Color:red ; } [ RU.localizedName = "коробка" ; ]
obj vase : Vase { weight = 1 ; color = Color:blue ; directlyIn(box) ; }

meta for Item.weight [ RU.localizedName = "вес" ; ]
```

- Метаданные `[ ключ = значение ; ЯЗЫК.ключ = значение ; ]` есть у всего: классов, объектов, свойств, значений перечислений.
  `localizedName` — имя, которое подставляется в тексты.

### Отношения: арность, кардинальность, шкалы

`rel имя<параметры>(Класс1, Класс2, ...) : вид ;` — субъект — объект класса, где объявлено отношение, в скобках
классы объектов связи. Один класс в скобках — бинарное отношение, два — тернарное.

Вид после `:` — одно из трёх:

| запись | что задаёт |
|---|---|
| `{a -> b}` | кардинальность бинарного отношения |
| `linear` или `partial` (можно с `{...}`) | шкала: порядок на объектах одного класса |
| `opposite \| transitive \| between \| closer \| further to <отношение>` | производное отношение, вычисляется из другого |

**Кардинальность `{a -> b}`**, `a` и `b` — число или `*`:
- `b` — сколько объектов может быть у одного субъекта;
- `a` — у скольких субъектов может быть один и тот же объект.

| запись | смысл | пример |
|---|---|---|
| `{1 -> 1}` | один к одному | у предмета одна этикетка, этикетка у одного предмета |
| `{1 -> *}` | один ко многим | ящик держит много предметов, предмет — в одном ящике |
| `{* -> 1}` | многие к одному | у предмета один владелец, у владельца много предметов |
| `{* -> *}` | многие ко многим — по умолчанию | — |

- Кардинальность разрешена только у бинарных отношений.
- Проверяется при валидации ситуации по связям объектов: лишняя связь — ошибка «too many outgoing/incoming links».
  Отношение с параметром считает связи без учёта значений параметра.

**Шкалы** — бинарные отношения внутри одного класса, без циклов:
- `linear` — линейный порядок («следующий»), кардинальность неявно `{1 -> 1}`, другая запрещена;
- `partial` — частичный порядок («родитель» в дереве), неявно `{* -> 1}`, справа допустима только `1`.

**Производные отношения** в ситуации не задаются, а вычисляются:
- `opposite to r` — то же отношение в обратную сторону, кардинальность — перевёрнутая у `r`;
- `transitive to r` — замыкание: связь через любое число шагов `r`;
- `between | closer | further to r` — тернарные отношения на шкале, объявляются с двумя классами в скобках:
  - `X=>between(A, B)` — `X` между `A` и `B`, порядок `A` и `B` не важен;
  - `X=>closer(A, B)` — `X` ближе к `A`, чем `B` (`X` между ними);
  - `X=>further(A, B)` — `X` дальше от `A`, чем `B` (`B` между `A` и `X`).

  Поверх самой шкалы «между» значит «соседи по цепочке», поверх `transitive` — на любом расстоянии.

`transitive`, `between`, `closer`, `further` строятся только поверх шкалы (по цепочке производных — в конце должна
стоять шкала). Кардинальность у производных, кроме `opposite`, — `{* -> *}`.

**Как это сказывается в выражениях:**
- `X->rel` требует ровно одну связь (с учётом указанных параметров): ни одной или несколько — ошибка при вычислении.
  Поэтому `->` безопасен для `{… -> 1}` и шкалы `partial` (если связь точно есть), а для `{… -> *}` нужен
  `X=>rel(Y)`, `forAny` или `find`;
- `X=>rel()` без объектов — есть ли у `X` хоть одна такая связь;
- `->` работает только с бинарными отношениями; тернарные проверяются через `X=>rel(A, B)`.

## Каркас дерева

```loqi
lambda isHeavy(X: Item) = X.weight > 3;

tpg Pack(X: Item, T: Item) {
    var C : Item = (X->containedIn);
    ask (isHeavy(X)) {
        true -> { conclude: error [ ... ] };
        false -> { conclude: subcall("fit", X, C, T) };
    } as heavyCheck
}
[
    note = "...";                            // метаданные дерева целиком
]

meta for heavyCheck [
    note = "...";
]
```

- Параметры `tpg` — переменные дерева. Главное дерево получает их из ситуации, вызванное — из `subcall` по позиции.
- Тело — операторы через `;`. Каждая ветка должна закончиться выводом: сборщик проверяет достижимость.

## Узлы

| запись | узел | что делает |
|---|---|---|
| `ask (expr) { v1 -> {...}; v2 -> {...} }` | вопрос | считает `expr` и идёт по ветке с этим значением: `true`/`false`, значение перечисления, объект. Значения без ветки роняют рассуждение — покрыть все или увести в `out` |
| `ask (cond) out false else { ... };` | вопрос | короткая форма для булевых: при `false` идём к следующему оператору, при `true` — в блок |
| `ask switch (expr) {...}`, `ask (expr) with trivial [cond] {...}` | вопрос | тот же вопрос, помеченный тривиальным (всегда или при `cond`): на нём не заостряют внимание студента |
| `ask tuple (e1; e2) { (a; b) -> {...} }` | вопрос-кортеж | переход по комбинации значений нескольких выражений |
| `var X : Класс = (expr);` | поиск | кладёт объект в переменную и идёт по `true`. Если объекта нет — выход `false`, а без веток его нет и рассуждение падает. Возможную пустоту сначала проверить через `ask` |
| `agg <метод> { _ -> {...}; _ -> {...}; correct -> ...; error -> ...; null -> ... }` | агрегация | считает все ветви (`_` — любое имя ветви), сводит их итоги методом и идёт по выходу с итогом |
| `cycle <метод> (cond с $X) with Класс X { _ -> {...}; correct -> ...; ... }` | цикл-агрегация | тело выполняется для каждого объекта `X`, подходящего под `cond`; итоги сводятся методом. Нет объектов — `null` |
| `while (cond) { body -> {...}; correct -> ...; ... }` | цикл | повторяет тело, пока `cond` истинно и тело даёт `null`; итог — итог последнего прохода |
| `conclude: correct [...]` | вывод | итог ветки — `correct`, `error` или `null`, с метаданными |
| `conclude: subcall("имя", a, b)` | вызов дерева | итог ветки — итог дерева `tree_<имя>`; его трасса вкладывается в текущую. Переменные вызванного дерева свои |
| `fragment:имя(X) [...]` | фрагмент | подставляет тело фрагмента при сборке (см. ниже) |
| `merge` | — | продолжает ветку копией операторов, идущих после охватывающего оператора |
| `debug:point("…")`, `debug:dump("…")`, `debug:assert(cond, "…")` | процедура | отладка; дерево с ними собирается только с отладочными метаданными |

### Последовательность, `out` и `merge`

Выход, ведущий в `out`, продолжает рассуждение со следующего оператора той же ветки. Так вложенность заменяется
цепочкой проверок:

```loqi
ask (X.weight > 10) out false else {
    conclude: error [ ... ];
};
ask (X.isFragile) out false else {
    conclude: error [ ... ];
};
conclude: correct
```

`merge` нужен, когда ветка сначала делает свою проверку, а потом должна пойти дальше как обычно:

```loqi
ask (X.isFragile) {
    true -> {
        ask (X.weight > 3) out false else { conclude: error [ ... ] };
        merge
    };
    false -> out;
};
conclude: correct
```

### Методы агрегации

| метод | итог | смысл |
|---|---|---|
| `and` | `null`, если есть `null` или ветвей нет; иначе `error`, если есть `error`; иначе `correct` | одновременные проверки, нужны все |
| `or` | `correct`, если есть `correct`; иначе `error`, если есть `error`; иначе `null` | достаточно одной удачной |
| `hyp` | как у `or` | равновероятные гипотезы о ходе рассуждения |
| `mutex` | единственный итог не `null` | взаимоисключающие проверки |

В выходах агрегации `true` и `false` — синонимы `correct` и `error`. Выходы лучше писать все и явно: пропущенный выход
сборщик превращает в `out` по умолчанию (для `and` — `correct`, для `or` и `hyp` — `error`, для `mutex` — `null`),
и он молча продолжает следующий оператор. Если следующего нет, как и для остальных пропущенных выходов, итог агрегации
становится итогом ветки без вывода. Обычное рассуждение это переживает, но дерево, вызванное через `subcall`, должно
заканчиваться выводом: если оно заканчивается агрегацией без выхода на такой итог, рассуждение падает.

## Выражения

| запись | значение |
|---|---|
| `X`, `T` | переменная дерева |
| `$x` | переменная квантора, условия цикла или поиска |
| `X.prop` | свойство объекта или класса |
| `X->rel`, `X->rel<index = 0>` | связанный объект (с параметром отношения) |
| `X=>rel(Y)`, `X=>rel(Y).param` | проверка связи; параметр связи |
| `X is class:Vase`, `(X as class:Vase)` | проверка и приведение класса |
| `X.class()` | класс объекта |
| `obj:box`, `class:Item`, `Color:red` | литералы объекта, класса, значения перечисления |
| `==`, `!=`, `<`, `>`, `<=`, `>=`, `X.compare(Y)` | сравнения; `==` у объектов — тот же объект |
| `and`, `or`, `not`, `c ? a : b` | логика и тернарник |
| `forAny Item x [фильтр] { cond }`, `forAll ...` | кванторы |
| `find Item x { cond }`, `findExtreme a [критерий] among Item b { cond }` | поиск объекта; крайнего по критерию |
| `X.weight = 3`, `X +=> rel(Y)`, `X -=> rel(Y)`, `+obj:Item({...})` | изменение ситуации: только в `conclude: ... with (expr)` и в процедуре `eval(expr)` |

## Метаданные узлов

Вывод получает метаданные прямо в `[...]`. Остальным узлам имя даёт `as`, а метаданные навешиваются отдельно:

```loqi
ask (X.isFragile) {
    true -[fragile]-> { conclude: error };          // имя выхода
    false -> out;
} as fragilityCheck                                  // имя узла

meta for fragilityCheck [ skill = "..."; ]
meta for fragile [ note = "..."; ]
```

- Имя из `as` пишется в метаданные узла как `alias`; явный `alias` в `meta for` важнее.
- Имя `_…` — служебная метка только для `meta for`, в `alias` не попадает.
- Алиас `out`-выхода: `ask (...) out[имя] false else {...}` или `-[имя]-> out`.

### Шаблоны текста

Строковые метаданные могут быть шаблонами:
- `${expr}` — любое LOQI-выражение; объект подставляется своим `localizedName` на нужном языке;
- `${X.class()}` — название класса объекта;
- `${X}[case='р']` — склонение подставленного значения;
- `${$name}` — контекстная переменная шаблона;
- варианты формулировки — тернарником: `${X.isFragile ? 'хрупкий' : 'прочный'}`.

## Лямбды и фрагменты

```loqi
lambda isHeavy(X: Item) = X.weight > 3;

fragment checkFragile(A: Item) {
    ask (A.isFragile) out false else {
        conclude: error [ RU.reason = "..." ];
    };
    conclude: null
}
```

- `lambda` — выражение-макрос, подставляется в место вызова при сборке.
- `fragment` — кусок дерева, подставляется при сборке: `fragment:checkFragile(X)`. Аргументы — только переменные
  дерева, рекурсия запрещена.
- Метаданные вызова `fragment:checkFragile(X) [ skill = "..." ]` заполняют выводы фрагмента. Свойство, заданное
  и во фрагменте, и у вызова, — ошибка сборки.
- Выводы фрагмента можно перенаправить: `fragment:f(X) { error -> {...}; correct -> out; }` или `fragment:f(X) out correct`.

## Приёмы построения

- **Цепочка вместо вложенности.** Проверки, каждая из которых может закончить рассуждение, пишутся подряд через
  `ask ... out false else {...};`, последним — вывод по умолчанию.
- **Гипотезы — `agg hyp`.** Каждая ветвь — один способ рассуждать: выводит ответ своим способом, сравнивает его
  с ответом студента и даёт `null`, если не совпало. Выход `null` агрегации — случай, когда ответ не объяснил ни один
  способ; вывод там может нести пояснение, почему такой ответ невозможен.
- **Шаги одного рассуждения — `agg and`.** Допущения, сделанные одновременно: итог `correct`, только если сработали все;
  `null`, если хоть один шаг не применим.
- **Перебор кандидатов — `cycle`.** Условие отбирает объекты (`$X`), тело работает с переменной `X`.
- **Длинное рассуждение — по деревьям.** Каждое решение — отдельный `tree_<имя>.loqi` и `subcall`; повторяющийся
  кусок внутри одного файла — `fragment`, повторяющееся условие — `lambda`.
- **Имена развилкам.** `as имя` у развилок и агрегаций, к которым относятся метаданные или которые надо узнавать
  в трассе.
- **Все выходы явно.** И у `ask`, и у агрегаций — чтобы не сработал неявный `out`.

## Метаданные, которые читает CompPrehension

Ключи не из LOQI, а из бэкенда `DecisionTreeReasonerBackend`: без них дерево собирается, но вердикт и объяснения
собрать нельзя.

| где | ключ | для чего |
|---|---|---|
| вывод | `skill` | навык, который вывод засчитывает (`correct`) или нарушает (`error`); несколько — через `;` |
| вывод | `hypothesis` | имя способа рассуждения. Обязателен у выводов не `null` внутри ветвей `hyp` |
| вывод | `RU/EN.explanation` | продолжение префикса дерева: со строчной буквы, с точкой в конце |
| вывод | `RU/EN.reason` | во что поверил студент — вариант для вопроса «почему вы так решили». Обязателен у ошибочной гипотезы |
| вывод | `muted = true` | вывод без объяснения |
| дерево | `error_prefix`, `hint_prefix` | начало объяснения ошибки и подсказки |
| дерево | `misreasoning_prefix`, `error_statement`, `clarification_prompt` | рамка «ответ верный, но рассуждение ошибочно», короткое «ответ неверен» и вопрос о причине. Обязательны у дерева с `hyp` |

Как агрегации читаются при сборе объяснений: ветви `and` — части одного рассуждения, ветви `hyp` с итогом не `null` —
разные рассуждения студента. Объясняют агрегацию только ветви с её итогом.
